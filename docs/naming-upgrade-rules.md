# 命名规则与洗版策略

洗版编辑窗口只显示明显的分组序号、中文及代码名称、启停和标签优先级；不再显示长算法说明及分组权重。后台评分定义和预览返回的分值保持原规则。

以太识律的命名和洗版预设均可添加多张卡片，各自保存配置，由整理归档任务选择对应ID。当前完成配置、命名求值和洗版评分决策；整理执行器仍未连接，不因预览或保存而移动、删除或重命名真实文件。

## 命名模板

编辑窗口分剧集命名、电影命名、多版命名；多版暂保留占位。剧集与电影分别保存源码字符串，可在可视化标签和源码之间切换。源码不支持表达式、脚本或任意模板函数，仅支持下列明确变量与字面文本：

| 类别 | 变量 |
| --- | --- |
| 基础信息 | 媒体标题`title`、原语言标题`original_title`、发行年份`year` |
| 媒体识别 | TMDB识别标签`tmdb_tag`、TMDB数字ID`tmdb_id` |
| 剧集专用 | 季集组合`season_episode`，例如S01E01 |
| 技术标签 | 分辨率`resolution`、帧率`frame_rate`、色深`color_depth`、流媒体平台`web_source`、片源类型`resource_type`、修订版本`revision`、资源效果`resource_effect`、视频编码`video_codec`、音频编码`audio_codec`、自定义匹配值`customization`、制作/发布组`release_group` |

源码变量使用`{变量名}`。绿色变量在每个路径区段中只能用一次，已用候选置灰；目录和文件名可各用一次标题或年份。米黄文本可重复添加，默认点号，双击或选择后点击“编辑文本”可修改；空值代表一个空格。文本仅在本段第一个变量之后、最后一个变量之前有效，段首段尾的文本不输出；例如需要在年份后保留右括号，后面还须有变量，默认目录模板的TMDB标签即在其后。文本原样连接，缺失事实渲染为空，不猜测缺失技术值，也不自动重写用户连接符。

橙色路径标签`/`独立创建目录，不能写入普通文本标签。路径每段必须含变量，禁止绝对路径、空段、上级目录结果、反斜杠和控制字符；最多8段、256个标签、源码8192字节。变量值的路径和文件名禁用字符会替换为下划线，不能由元数据创建额外目录。最终每段及文件名称有字节长度保护。

原文件的完整后缀自动保留，不开放`ext`等截图结构之外的变量。例如`film.mkv`保留`.mkv`，`film.mkv.cas.strm`保留`.mkv.cas.strm`；常规STRM、share和ed2k复合后缀同样保留。示例使用固定的电影/剧集事实与`.mkv`，在插入变量下分别显示目录、文件名称，不访问TMDB或云盘。前置识别替换、模板命名、后置命名替换/发布组是后续执行器依次调用的阶段，不把模板配置套用到现有文件管理改名操作。

标签可通过手柄拖拽，或选择后用前移/后移按钮；手柄支持Alt+左右键。源码非法时保留草稿并禁保存，两套模板都通过校验才可保存。临时添加路径后可继续插入变量完成该段。恢复默认只改编辑草稿，保存后生效。

## 洗版总分

10个分组为：分辨率、片源类型、视频编码、音频编码、HDR类型、色深、帧率、字幕、文件格式、文件大小。默认全部开启，初始标签及候选依用户截图提供；可移除、重新添加候选或调整顺序，不能写入未知分组/标签。

仅开启的分组参与，按开启顺序从上到下依次给予最高分`10、8、6、5、4、3、2、2、1、0.6`。关闭分组会跳过，后面的开启分组依次向前补位，上下移后重新赋分。某组最高分为W、有M个已选标签时，第i个标签（从0起）得分为`W × (M−i) / M`；例如最高分10且选中4项，从左到右为`10、7.5、5、2.5`。未匹配或无已选标签得0分，一份文件在一个分组只取最高匹配分，不重复累计。总分直接累加各组实际分数，不再额外乘一次权重；后排分组的合计可以超过前排分组的差额，不是首次不同即结束的逐组比较。

大小写及常见等价拼写共享最高匹配位置，例如2160p/4K、H.265/HEVC、Dolby Vision/DV、10-bit/10BIT，不因同一质量的拼写不同洗版。中文字幕和有字幕可匹配对应字幕标识；音轨基础编码可匹配其声道变体。文件格式识别允许剥离STRM专用后缀后再比较原媒体扩展名。

文件大小分组使用本次两版本中较大文件为该组最高分W，另一份按`W × 大小 / 较大大小`计分，两者均为0则都0分；因此原始字节不会压过其他分组，比较分数仅供本次二者比较。默认全部开启且大小在最后时W为0.6，仅开启大小一组时W为10。未知大小以0表示，不推测真实大小。组间只保留右上角上下移按钮，中文名称旁同时显示代码标签，如“分辨率（resolution）”；组内标签可拖拽、按钮前后移或Alt+左右键。关闭后保留原标签顺序，重新开启恢复参与。

总分高者获胜，同分保留现有版本且不自动搬走另一份。有明确胜负时，落败者的处置决策为移到整理归档任务的`failureDirectory`（当前表单名称“冗余归类”，需求亦称失败处理）；目录为空时保留，不继承黑名单的回收站回退。后续执行器必须先确认两份是同一作品/同一集，才能比较并执行处置，当前纯比较函数不访问文件系统或存储。

## 配置与接口

`rulePresets`中命名卡片持有`naming: {tv,movie}`，洗版卡片持有`upgrade: {groups:[{id,enabled,values}]}`。每卡独立，元数据旧客户端只修改名称/说明时保留其原定义；旧卡没有定义时仅在读取响应中补默认，读取不重写磁盘。沿用主配置事务、完整性认证及加密导出导入，导入也严格校验变量和评分配置。

受保护接口：`GET /api/naming-rules/catalog`、`POST /api/naming-rules/preview`和`GET /api/upgrade-rules/catalog`、`POST /api/upgrade-rules/preview`；全部返回`Cache-Control: no-store`。洗版目录返回固定权重序列，预览接受明确的事实列表与字节数，返回各组最高分、实际分数及总分；不探测文件或操作失败目录。保存仍走原预设CRUD接口，不新增后台执行任务。
