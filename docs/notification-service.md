# 通知服务与 TG 链接转存

侧栏“通知服务”位于辅助工具之后，包含“TG 通知”和“链接转存”。TG 设置表单与账号安全面板等宽，输入框40px、操作按钮36px；转存目录编辑使用640px标准窗口。

## TG 接入

- Bot Token：从 Telegram 的 BotFather 创建机器人后获取，不是自己的账号登录凭据。
- Chat ID：指定接收消息和允许交互的会话数字ID；私聊为正数，群组通常为负数。先与机器人发起会话，或将机器人加入指定群组。
- 授权用户 ID：允许发起转存的 Telegram 用户数字ID，支持分号、逗号或空白分隔，最多20个。私聊未填时保存采用该正数Chat ID；群组必须明确填写授权用户，不能只凭群组ID开放给所有成员。
- 开关默认关闭。保存配置后可“测试通知”，先核验机器人，再向已保存的Chat ID发送测试消息。开启后使用getUpdates长轮询，无需公网端口或Webhook；同一Bot不能同时由其他服务轮询。已有Webhook时明确报错，项目不会自动删除它。

只有Chat ID及发送用户ID同时匹配，且不是机器人发送者，才处理消息/图片说明中的官方HTTPS分享链接。未知链接、其他会话、其他用户和编辑消息不触发云盘写入。单条消息最多50个分享；同链接不同提取码报错，不静默选取一个。当前通知范围是连接测试、TG转存交互及其执行结果，不宣称推送所有系统事件。

Token通过现有AES-GCM字段保护及配置完整性协议保存，GET不返回Token；留空保存保留已存值。配置、开关和目录卡片存于`/config/state.json`的`notifications`，无需新增配置模块格式；勿手动破坏完整性封装。不要公开Token、分享口令或运行态文件。

## 链接转存目录池

115、原生移动、夸克各有独立目录池。目录卡片保存云盘类型、存储池、目录ID和完整路径，可再次选择同类型其他存储或目录，支持删除、拖拽排序及Alt+上下方向键排序。组内顺序持久化，Bot按此顺序显示；没有卡片时该类型不启用TG转存。

仅一个目录卡片时，发送匹配类型分享即授权转存到该目录，不增加选择和确认；配置多个卡片时先在Bot消息中选择目录，再点击“确认转存”，取消不会转存。回调绑定发起用户、Chat ID、消息ID、随机任务ID和选项，10分钟过期，旧消息不能替换成其他用户或目录执行。目录修改或删除、账号停用、凭据变化及TG授权变化都会停止尚未提交的批次，不静默更换目标。已在途的上游请求不能撤销，应核对实际结果。

转存与网页分享复用目录读取、计划和单批提交：完整保留分享层级，每批最多499个文件，同名跳过，不覆盖；移动20万扫描保护、其他网盘既有限额和超时不变。全局仅一个TG执行任务，最多32个待处理交互，结果保留最近约200条；不并发轰炸云盘。夸克按任务查询确认完成再处理下一批，115及移动返回任务编号仅报告“已提交”，不冒充云端完成。

## 回执与日志

TG偏移、待处理任务及写前批次意图保存于`/data/runtime/state.json`的`telegramRuntime`，原始分享作为加密secret字段暂存，终态清除。新Token首次接入只建立最新偏移，不执行积压消息；已确认的更新在外部写入前持久化，重复更新/确认不再次提交。服务重启时未完成任务及确认标记中断，清除链接，不自动重放云端转存。缺失运行态重新建立偏移，不猜测上次结果。

配置变更、开始、逐批提交/跳过、完成、失败和中断写入“系统日志→通知服务”，含任务标识`TG:任务ID`、存储名、目录、资源简名及实际提交数。Token、Cookie、提取码和完整分享地址不进入日志或回调数据。网络异常和结果不明时停止后续批次，不自动重复写入；检查日志及云盘实际目录后再决定是否重新发送。

协议参考：[Telegram Bot API](https://core.telegram.org/bots/api)，使用getMe、getWebhookInfo、getUpdates、sendMessage、editMessageText和answerCallbackQuery，固定api.telegram.org、HTTPS且不跟随重定向。模拟API、重启与浏览器测试不等同真实机器人、群组权限或真实云盘转存联调；首次部署须单独验收。
