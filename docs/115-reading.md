# 115 的本机读取

本地挂载和 WebDAV 始终由 Aether 服务器读取文件，不使用浏览器 302。后台文件下载默认 302，浏览器下载成功并不能证明容器的读取链路正常。

本地挂载读取 115 使用 4 MiB 有界分块，同一存储池同时最多两路上游下载，每路限制为 50 MB/s（50,000,000 字节/秒）。不同文件、不同挂载共享该存储池的两路配额，读完一块就释放；并非强制每个文件启动两路下载。实际速度仍取决于上游、网络和磁盘，这不是速度保证。缓存命中不占下载配额、不做网络限速；每个打开的云文件保留一块已校验的热缓存，避免内核小请求重复读取和校验整块。WebDAV 不套用本地挂载的并发限额。

115driver 返回的下载请求头包含认证 CK 和响应下载票据。此前 Aether 丢弃了认证 CK，仅保留响应票据；需要 Cookie 的下载请求可能因此持续返回 403，重新获取链接也不会补回 CK。

现在仅对 HTTPS、默认端口的官方 `115.com`、`115cdn.com`、`115cdn.net` 域名及其子域保留驱动提供的 UID/CID/SEID/KID。非官方域名、HTTP 和非标准端口不发送这些凭据；跨域重定向继续清除 Cookie 和认证头。不会向浏览器返回认证 CK。

服务器内部读取使用普通浏览器 UA，获取链接和读取使用相同 UA；播放请求仍保留客户端 UA。API 与文件读取复用默认传输层，辅助工具代理不自动接管网盘流量。读取拒绝后的备用接口仍最多尝试一次，不重放上传或其他写操作。

验证包含需要认证 Cookie 的 HTTPS 模拟服务、WebDAV/挂载共享读取器、偏移读取及跨域凭据隔离。真实 115 账号和 Linux FUSE 内核仍需部署验证；本次修正不证明所有 403 都由缺少 Cookie 引起，也不替代现场读取验证。
