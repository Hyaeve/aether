## Go 测试分片

`go test` 默认的10分钟超时针对整个包测试进程，不是单个测试。报错中的 `running tests` 列出超时瞬间仍在运行的测试；例如 `TestTransferLogBound (8s)` 不能单独证明这个测试卡住了10分钟。

CI 将完整 Go 测试分成8片。每片先在当前平台以相同竞态构建模式执行测试发现，再按顶层名称确定性分配；跨包同名测试进入同片，避免全包 `-run` 过滤引起重复或遗漏。普通测试、可执行示例和 Fuzz 种子均参加，子测试不单独过滤。只执行 benchmark 的负载与原 `go test -race ./...` 一样不默认运行。

每片保留 `-race`、`-count=1` 和默认包级超时，不添加 `-short`、`-skip` 或更长超时。Go 返回非零立即失败；即使退出码是0，仍检查发现清单与实际顶层成功/既有跳过结果是否一致，缺少、重复或意外多跑均失败。原测试主动按平台跳过的规则不改变。

8片全部完成且成功，以及前端验证成功后，才能构建发布镜像。关闭 matrix 的 fail-fast，某片失败不会取消其他片的诊断。

Linux 开发环境安装 Go 对应的 C 编译器和 FFmpeg 后，从仓库根目录运行同一分片：

```bash
node --test scripts/*.test.mjs web/tests/*.unit.mjs
node scripts/go-test-shards.mjs --index 0 --count 8
```

`--index` 为0至7。可依次运行全部8片：

```bash
for shard in 0 1 2 3 4 5 6 7; do
  node scripts/go-test-shards.mjs --index "$shard" --count 8 || exit "$?"
done
```

`--plan` 仅生成发现清单和分配，不执行用例，不算测试通过。缺少 CGO/C 编译器的本地环境可显式加 `--no-race` 验证分片和普通测试，但不能据此宣称竞态测试通过；CI 不使用该参数。Windows 发现清单不包括 Linux 专属构建文件，不能代替 Linux 验收。

## 失败产物

每片始终上传 `go-test-results-片号`，内容来自 `test-results/go-shard-片号/`：

- `discovery.jsonl` 与 `discovery-stderr.txt`：发现阶段输出；编译或环境失败也保留。
- `manifest.json`：完整测试数量、各片数量、本片包名和测试名、实际运行参数。
- `tests.jsonl` 与 `stderr.txt`：实际 Go 测试的完整输出，保留超时堆栈、断言失败或竞态报告。
- `result.json`：仅在 Go 成功且清单核验通过后生成，记录数量和实际耗时。

先查看失败步骤，再区分 `panic: test timed out`、`WARNING: DATA RACE`、`--- FAIL` 或编译错误。进程退出码1本身不能定位原因；无浏览器产物可能只是尚未执行浏览器步骤，并非浏览器测试故障。

普通测试和性能诊断都使用临时配置与数据，不读取真实部署凭据。源码已推送、CI通过、GHCR镜像发布与用户部署验收是不同状态，须分别确认。

## WebDAV退出与临时目录清理

共享Range读取在应用取消时异步结束传输并持久化日志。只取消context并等待普通任务，并不能证明这些回调已经停止写入；`TempDir RemoveAll cleanup`与日志保存失败可能来自退出时仍在进行的原子写入，不应通过重试删除、等待固定时长或忽略错误处理。

应用退出与`testApp`清理均须先关闭共享读取登记，停止空闲计时器，并同步完成或阻止在途收尾写入，再清理测试目录。回归覆盖阻塞收尾时临时目录不能先删除、已完成/失败状态和真实字节保留、取消后不新建会话、待收尾会话不被提前淘汰，以及并发打开和重复关闭。原暂停、请求取消隔离、唯一字节进度和失败冷却断言保留。

## 浏览器布局与截图

汉字字距回归使用混排文本逐一核对相邻汉字的0.1em增量，以及汉字与字母/数字边界零增量，保留严格0.035px精度。WebKit的文字Range矩形可能按整像素取整，另保原Range诊断，以实际行内元素矩形校验布局精度；不能因此放宽像素断言。同时核对原文选择/复制、可访问名称、输入原值、搜索动态更新、窄屏溢出和长路径省略，继续覆盖有界虚拟列表，不以构建成功代替界面验证。

数字统计以受控时钟验证1500ms上限、大数小数的整数目标、减速步长和更新频率；真实SFC组件还须验证超长duration被截断、中途新数值不顺延期限、减少动态效果和卸载清理。文件管理内联改名按名称单元格实际内容宽度验收，不侵入大小列，日夜及手机均覆盖；115改后缀验证确认/取消、忙碌禁重复提交、失败保留原条目和新ID原地替换，不把前端模拟当真实云写。

115改后缀后端回归分别覆盖秒传握手的零媒体读取/一次有界挑战/拒绝普通上传、严格Range及SHA1、独立新ID/PickCode、重名和源身份变化、配置修订、回收读回与失败保留。原生加密请求仅用拒绝响应验证线协议，成功/失败编排使用受控提交回调；不能据此宣称真实115已命中或承诺即时完成。写前意图须跨重启、Cookie轮换和配置导入保留，且不进入配置导出；错误日志不得泄露上游正文或凭据。

侧栏断点、通知时间格式及海报虚拟行距均保留严格的浏览器断言。窗口缩放后的同行坐标在一次布局读取中采样，并等待目标视口就绪，避免把不同帧的位置误判为错位；不增加坐标容差或测试时限。

音频侧栏滑入时，关闭与折叠按钮也须在同一帧比较相对坐标，保留左右停靠的严格方向要求；不能把两次不同动画位置的绝对坐标相减，也不通过关闭动画或固定等待掩盖测量问题。

备份规则标题栏的设置和添加按钮在窄屏仍与栏目同行，只有传输任务的搜索操作区允许换到下一行；分别覆盖700px断点两侧及320px小屏，不能把共享组件的换行样式误用于备份栏。主页面滚动轨为8物理像素，命名历史与其他整页列表使用同一规范，不能继续按旧7px断言；DPR及缩放校准仍独立验证。

共享截图工具先等待两帧，帧时钟暂停时最多等待100ms后继续实际截图；该回退不意味着截图成功。实际截图仍限时5s，仅对已识别的临时截图协议错误最多尝试3次，其他错误或第3次失败直接报告。截图、trace与错误上下文仍保留，相关单元测试与其他前端单元在CI完成npm依赖安装后、浏览器测试前运行；不依赖开发机已有的node_modules。

云管理须分别验证会话缓存、分页合并、明确刷新、配置修订/登录失效和迟到响应；窄屏不仅检查工具栏外框，还核对每个按钮和末级路径文本的实际边界。秒传主记录跟随页面滚动，分页可达性通过滚到分页按钮后验证，不再使用旧内部滚动假设；固定页高须计入边框。

Cron回归覆盖15分钟边界、跨小时的短间隔、重试严格大于120分钟及旧配置启动/调度暂停。清理回归只用模拟115传输，保留确认、未知回执重启不重放、目录/内容变化、1970零时间、末次空目录检查及存储设置变更的安全断言；模拟通过不等于真实账号清理已验收。

## 模拟登录与后台校验

只模拟`/api/auth/status`登录成功，不会让隔离后端获得真实会话。编辑器挂载后还可能请求Cron校验或后台状态；这些接口也必须包含在同一测试夹具中，不能遗漏后再由真实后端返回401。共用API遇401会正确清除前端登录状态，卸载编辑窗口；此时报告的选择框或“更多选项”点击超时、元素被移除，是会话失效后的表现，不应直接归因于滚动或渲染性能。

`scrape-participation.spec.js`为Cron初始校验、流量和替换通知轮询提供明确响应，未定义的接口记录并返回测试错误，避免意外穿透到真实后端。编辑前登记校验响应等待，先核对HTTP200及请求表达式，再继续保留原同行、选择、保存与库筛选断言；不使用固定延时、强制点击或延长超时绕过。另验证HTTP200的规则错误只显示校验警告且编辑仍可操作，而真正401仍须关闭编辑并回到登录，不能为测试修改产品鉴权逻辑。

`quark-workspace.spec.js`同样明确模拟工具页挂载时的115签到、文件夹清理、回收站清理、同播、插件状态，以及流量和替换通知；未知接口返回测试错误，不穿透隔离后端。打开编辑器前先核签到及文件夹清理响应成功，再验证原绑定、保存、解绑确认和手机布局。两种新增配置请求真实返回401时仍必须回登录；非认证的配置读取失败不能误清会话。
