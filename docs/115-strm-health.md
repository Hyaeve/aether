# 115 STRM 与存储健康暂停

STRM输出目录的内部登记不再把挂载设备号变化一律视为目录替换。设备号变化但目录inode相同时，会先按内部登记核验现存产物，再恢复关联。目录inode也发生变化，或旧owner已删除尚未迁移时，可手动执行“全量同步”：核验现存登记文件内容一致后恢复；空目录可重新绑定，有无法核验或已修改的登记文件则保留现场并停止。未知文件不纳入登记；恢复不会创建owner，也不会先清空生成库。执行期间仍校验打开目录与当前路径的身份，目录中途替换会停止。这是本地输出登记问题，与115生活事件接口、pickcode和云端文件权限无关；单独删除owner不代表目录inode必然改变。

更多选项中的“级联删除”使用整行扩展名输入框，位于STRM刮削下一行。留空关闭，多个扩展名用英文分号分隔，右上角图片、数据按钮可快捷增减类型。旧已开启配置显示原扩展名（未配置时使用原默认值），旧关闭配置显示空值。既有同名、作品/季度公共刮削保护、外改保留及删除阈值不变。

原生 115 STRM 必须带真实账号 ID：

```text
http://主机:端口/d/333554321/cq391yoe47hu5dd6u/爱的迫降.S01E01.ts
http://主机:端口/d/333554321/cq391yoe47hu5dd6u
```

两种设置都包含账号 ID；默认 `pickcode_name` 在纯 pickcode 后使用独立的完整文件名路径段，`pickcode` 仅保留账号和纯 pickcode。pickcode 后不再拼媒体扩展名或 `?/`，文件名按 URL 路径段安全转义，播放时核对登记名称。ID 从 CK 的 UID 数字前缀提取，不写入完整 UID、CK 或 Token。账号 ID 会出现在链接中，分享链接时注意这一点。

同一真实 115 账号不能重复添加，即使存储池名称、设备、根目录不同，或另一存储池已停用。更新同一存储池的同账号 CK 可以正常保存。添加、编辑和配置导入均在后端校验。已有重复配置不会自动删除，但须手动处理重复存储池后才能为它生成新链接。

旧的无账号 ID `/d/{pickcode}`、`pickcode.扩展名?/文件名` 和查询串承载文件名的地址不兼容，返回404；已有旧加密索引也不恢复这些入口。已有 STRM 不自动修改，需要在系统设置选择“覆盖生成”后重新执行普通STRM任务。旧加密索引不自动删除，新映射使用“账号 ID + 纯 pickcode”隔离，仍只允许播放登记过的文件。存储池换号后，旧账号路径拒绝访问，不静默转到其他账号。

有效健康检查结果为异常时，关联任务卡片和备份规则卡片标红并显示临时停止，手动执行和计划触发被阻止；冷却截止并不等于恢复，须成功检查。备份的所有源和目标位置，以及旧任务显式绑定的账号均纳入关联检查。正在执行的工作收到取消信号，备份继续使用已有取消与补偿保护，不把半完成过程误报成功。

成功检查后自动解除健康暂停，必须所有相关存储均恢复。不会改变用户启用开关、Cron 或手动模式。计划任务按原有计划继续，手动任务等待手动执行；不自动重放已中止的手动或破坏性操作。历史执行结果保留，健康暂停提示是当前状态而不是永久关闭配置。
