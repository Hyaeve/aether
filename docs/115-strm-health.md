# 115 STRM 与存储健康暂停

原生 115 STRM 必须带真实账号 ID：

```text
http://主机:端口/d/333554321/cq391yoe47hu5dd6u.ts?/爱的迫降.S01E01.ts
http://主机:端口/d/333554321/cq391yoe47hu5dd6u
```

两种设置都包含账号 ID；区别仅为是否显示扩展名和文件名。ID 从 CK 的 UID 数字前缀提取，不写入完整 UID、CK 或 Token。账号 ID 会出现在链接中，分享链接时注意这一点。

同一真实 115 账号不能重复添加，即使存储池名称、设备、根目录不同，或另一存储池已停用。更新同一存储池的同账号 CK 可以正常保存。添加、编辑和配置导入均在后端校验。已有重复配置不会自动删除，但须手动处理重复存储池后才能为它生成新链接。

旧的无账号 ID `/d/{pickcode}` 路由不再播放。已有 STRM 不自动修改，需要重新全量生成。旧加密索引不自动删除，新映射使用“账号 ID + pickcode”隔离，仍只允许播放登记过的文件。存储池换号后，旧账号路径拒绝访问，不静默转到其他账号。

有效健康检查结果为异常时，关联任务卡片和备份规则卡片标红并显示临时停止，手动执行和计划触发被阻止；冷却截止并不等于恢复，须成功检查。备份的所有源和目标位置，以及旧任务显式绑定的账号均纳入关联检查。正在执行的工作收到取消信号，备份继续使用已有取消与补偿保护，不把半完成过程误报成功。

成功检查后自动解除健康暂停，必须所有相关存储均恢复。不会改变用户启用开关、Cron 或手动模式。计划任务按原有计划继续，手动任务等待手动执行；不自动重放已中止的手动或破坏性操作。历史执行结果保留，健康暂停提示是当前状态而不是永久关闭配置。
