# 本地目录列举的保守优化

## 调查结论

旧的 `rawList` 本地分支通过 `os.OpenRoot` 打开目录，再一次性 `ReadDir(-1)`，最后转换为 `[]File`。Go 1.26 的 Unix 实现对 Root 内的目录条目会立即用目录描述符相对的 `fstatat` 获取元数据，`entry.Info()` 复用该结果；Windows 也直接复用目录枚举所得元数据。因此这不是每个条目重复获取元数据的问题，不能通过删除 `Info()` 来修复。

保留真实大小和文件夹修改时间仍需要这些元数据。慢磁盘、网络文件系统和超大目录的 I/O 时间无法单靠本次调整消除；未测量用户的实际目录，不认定已找到现场延迟的全部原因。

## 独立实现

新增 `internal/app/local_list.go` 的 `localRawList(ctx, s, dir)`：

- 保留 `relative` 校验、`os.OpenRoot` 和根目录约束，不使用拼接后的绝对路径进行扫描。
- 使用 `Readdir(256)` 分批直接取得元数据，减少 `DirEntry` 包装和整目录中间切片；最终仍返回完整当前目录，不递归遍历。
- 每批读取前后检查取消，取消及读取错误不返回部分列表。系统调用进行中仍无法立即中断。
- 继续跳过符号链接，允许 Root 内原本可安全访问的目录链接，拒绝链接逃逸。保持 ID、原始顺序、大小、修改时间及非 nil 空列表语义。
- 不增加缓存、后台任务或并发元数据读取，不改变现有目录缓存及刷新逻辑。

## API 接入

`drivers.go` 的本地 `rawList` 分支使用：

```go
case "local":
    return localRawList(ctx, s, dir)
```

不改变其他存储分支；不在此层新增名称排序或文件夹优先排序。

## 验证

新测试直接调用独立函数，并与保留的旧实现进行比较：跨批次列举、空目录、嵌套路径、文件及文件夹修改时间、大小和 ID、路径越界、缺失目录、文件当目录、内部/外部/失效符号链接、取消后不返回部分数据，以及重读后的修改/删除可见性。

```powershell
go test ./internal/app -run '^TestLocalRawList' -count=3 -v
go test ./internal/app -run '^$' -bench '^BenchmarkLocalRawList$' -benchmem -count=3 -benchtime=1s
```

基准使用临时目录，比较旧实现和新实现的 256/4096 项热目录列举，不访问用户数据。当前 Windows amd64 测量中，256 项每次分配约从 159 KB 降至 110 KB，4096 项从 3.94 MB 降至 3.51 MB。耗时存在波动，不据此承诺显著提速或 Docker/Linux 上相同收益。

Linux amd64 仅做测试交叉编译，未运行真实 Linux 文件系统或 FUSE。API、目录刷新和文件服务回归在接入后统一验证。

五项本地列举专项连续三轮通过（符号链接用例实际执行、未跳过）。发布验证结果见版本说明；测试只使用临时目录，未修改用户数据。
