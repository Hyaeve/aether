# 媒体深度删除

内置插件位于“Emby 通知”之后。默认关闭，选择需要联动的以链后保存，首次启用或扩大联动范围需要确认。窗口分为联动配置、删除记录，记录每页20条，最多保留500条显示记录。

## 接入

1. 在“以太链接”创建并启用 Emby、Audiobookshelf 或飞牛影视以链。
2. 在以链编辑的“更多选项”填写 **Aether媒体目录**，即Aether能读取的STRM库根目录。若媒体服务使用不同挂载位置，填写 **媒体服务目录**。例如 `/media` 映射到 `/strm`；目录应为库根，而非将被整部删除的单个作品目录。
3. 在插件中选定以链并启用。客户端通过该以链的反代地址访问媒体服务，在媒体服务内主动删除文件或作品。

**直接连接原媒体服务的删除请求不经过Aether，不会触发本插件。** 无需将普通入库通知改成删除Webhook，也不会从定时扫库中“少了一个条目”推断源文件应删除。

Emby及飞牛的Emby兼容接口识别 `DELETE /Items/{Id}`、批量 `DELETE /Items?Ids=...` 和对应的 `POST .../Delete`，兼容 `/emby` 前缀。ABS仅识别要求删除文件系统内容的 `DELETE /api/items/{id}?hard=1`，数据库软移除不联动。飞牛使用其Emby兼容接口；上游只提供播放URL而不提供原始STRM路径时，无法安全还原删除范围，会拒绝联动。没有适配飞牛其他私有原生删除协议。

## 删除范围

- 普通 `.strm` 才参与；`.cas.strm`、`.share.strm`、`.ed2k.strm`（含大小写变体）排除。普通文件名伪装的CAS/ED2K内容同样不能进入源文件删除链路。
- 先读取原始条目路径；Series/Season等作品容器完整分页枚举其后代。单个文件只处理自己的指针；整部作品处理该作品中所有普通STRM指向的源文件，去重后按存储池及父目录分批执行，每批最多200个文件。
- 支持项目签名播放URL、已登记115 pickcode、签名夸克URL，以及可唯一匹配已配置根目录的本地、OpenList、WebDAV目标。外部地址、歧义映射、符号链接、来源仍是指针文件、缺失或已改变的来源均拒绝，不能凭任意URL查找并删除网盘文件。
- 源文件沿用存储池的删除方式，包括支持回收站的驱动。不会清空回收站，也不根据作品目录名递归删除未知文件、字幕或刮削文件；作品范围由实际普通STRM清单决定。

## 执行与回执

删除范围查询只使用发起删除的客户端身份，上游拒绝时不回退到服务账号。原始删除请求仍由媒体服务验证权限；仅HTTP200/204且每个待联动STRM确实消失后进入源文件阶段。STRM残留、重建、路径/配置变化、来源身份变化、任务占用或上游失败都会保留源文件。目录及原始STRM在删除前核身份和内容，源文件在提交前重新读父目录核标识、名称、大小、时间和可用摘要。

运行占用针对所选指针及源文件，不锁整个媒体库。相同父目录在每个阶段内复用一次新鲜枚举，阶段间重新读取；不是持久目录缓存。预读取限45秒、源删除限2分钟；聚合范围及新鲜枚举均有十万项上限，目录遍历最多一万个目录节点，不进行媒体正文下载。

每次写操作前保存加密意图，云盘确认后增加已处理数。中断、超时或结果不明不会自动重试，重启也不重放；已提交或未确认的同一源文件回执保留，恢复源文件后再次删除仍需人工核对。多文件云端操作不是跨存储事务，部分已完成时记录实际确认数量。配置修改在插件运行中拒绝。

配置在加密配置中保存为 `mediaDeepDelete`；独立加密回执位于 `/data/runtime/media-deep-delete.json`，不进入配置导出。运行日志模块为 `media-deep-delete`。插件不会自动启用、修改真实媒体库或对原媒体服务安装组件。

主动删除与扫库移除的边界参考 [StrmAssistant 深度删除说明](https://github.com/sjtuross/StrmAssistant/wiki/%E6%B7%B1%E5%BA%A6%E5%88%A0%E9%99%A4-(Deep-Delete))，接口依据 [Emby LibraryService](https://dev.emby.media/reference/RestAPI/LibraryService.html) 及 [ABS删除控制器](https://github.com/advplyr/audiobookshelf/blob/master/server/controllers/LibraryItemController.js)。实现独立编写，未复制参考项目源码。
