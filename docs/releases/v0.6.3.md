# v0.6.3

本版基于 v0.6.2，新增通知服务模块，并整合筛选快捷组、任务漫画扩展名与移动分享转存改进。

## 通知服务

- 侧栏辅助工具后新增“通知服务”，包含“TG 通知”和“链接转存”。TG 表单与账号安全面板等宽，支持 Bot Token、Chat ID、授权用户 ID、启停、保存和测试消息。
- 115、原生移动、夸克分别维护转存目录池，支持添加、再次编辑、删除及拖拽排序；配置由服务端持久保存，Bot 按目录池顺序展示。
- 未配置目录时不转存；仅一个目录时直接排队；多个目录时先选择再确认。只接受指定会话和授权用户的官方 HTTPS 分享链接，回调绑定用户、会话、消息及任务并在十分钟后失效。
- 复用网页分享转存流程，每批最多 499 个文件，保持目录层级、同名跳过和结果不明不重放。TG 单任务串行执行，夸克查询完成后继续；115、移动仅取得任务编号时报告“已提交”。
- 配置及 Token 使用既有加密和完整性机制；运行态保存更新偏移和批次意图，重启中断未完成任务，不自动重放。开始、逐批结果、完成及失败可在“系统日志 → 通知服务”查看。
- 使用 Telegram 长轮询，不新增公网 Webhook；已有 Webhook 不自动接管。通知范围为连接测试、TG 转存交互及结果，不代表所有系统事件通知。详见 [通知服务说明](../notification-service.md)。

## 扩展名快捷组

- 备份筛选和 115 秒传监控的五组扩展名快捷按钮支持再次点击收回：未选齐时补齐，全部选中时移除整组，保留组外自定义项。
- STRM、CAS、ED2K 任务的媒体扩展名增加漫画快捷组：`cbz;cbr;zip;rar;epub;pdf`，书本图标及橘黄色选中态。沿用整组切换，不改变默认扩展名或增加漫画阅读能力。

## 移动分享转存

- 原生移动分享扫描保护从 5000 项提高至 200000 项，文件与目录合计，仍完整读取后按父目录分批，每批最多 499 个文件。保留两分钟扫描、32 层深度及响应大小等保护，真实网络可能先达到超时。
- 大量取消勾选改用集合与父路径匹配，避免逐项遍历所有排除项；115、夸克与独立链库的既有限额不变。
- 带提取码的移动分享统一为 `https://yun.139.com/shareweb/#/w/i/分享码?pwd=提取码`；剪贴板、粘贴、失焦及提交保持一致，同码合并、冲突阻止提交。
- 移动、夸克的 `pwd=...` 与 115 的 `password=...` 只高亮文字，不套背景框，保留大小写、输入选择及滚动。

## 升级与验收边界

- 新增 `notifications` 配置与 `telegramRuntime` 运行态，旧配置默认不启用 TG，不改已有存储及任务。Token 不回显，留空保存保留已存值；群组必须指定允许交互的用户。
- 本地验证覆盖 Go 全包、浏览器回归、单元、构建与桌面/手机日夜截图；最终结果写入本地整版本总结。本地通过不等于 GitHub CI 或镜像构建通过。
- 无真实 Bot、群组权限或云盘写入联调；Docker、FUSE/NFS 和实际播放器仍须部署验收。不绕过上游授权或浏览器限制，不将模拟接口结果表述为真实转存成功。
