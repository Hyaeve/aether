# 传输与备份资源设置

传输配置位于 `/config/transfer/settings.json`，备份资源配置位于 `/config/transfer/resources.json`。使用现有带完整性校验的 JSON 模块事务保存，执行记录和暂停操作计划位于 `/data`，不会把运行进度写回配置文件。旧版本首次升级创建默认配置；已经创建的模块丢失或校验失败会拒绝启动，不静默覆盖。

## 传输设置

- 最大上传/下载速度：0 表示不限速，单位可选 KB/s、MB/s，分别按 1024、1048576 字节计算。各方向共用令牌桶，而非每个文件各自获得一份速度。允许最多 32 KiB 的短时突发，后续持续流量受限；等待支持取消。
- 最大预处理任务数：默认 5，限制后台文件接收暂存、备份源读取/校验暂存和提供商上传前处理的并发。备份扫描有自己的并发控制，不将云端 API 查询计作文件预处理。
- 最大上传任务数：默认 5，限制后台文件接收、WebDAV/FUSE 写入和受控本机文件发布的并发；排队时可以取消，退出或失败归还槽。减少上限不强制中断正在进行的任务，后续等待空位。接收和云端发布统一先申请上传槽，再申请预处理槽；备份源暂存结束先释放预处理槽，再等待上传，避免相互占槽死锁。
- 上传延迟：默认 10 s，仅针对本地新建 `upload-*` / `pending-*` 暂存文件，在文件最后修改时间后等待该间隔再上传。已经校验的备份快照不人为延迟，现有文件的直接下载不受影响。
- 跨云复制使用本地临时文件：默认开启。单向备份同一个云端源文件复制到多个目标时，共用一次已完整读取并校验的本地快照；关闭后各目标分别暂存读取，仍校验完整长度。不能在没有安全快照的情况下直接发布；双向同步的循环覆盖保护始终要求暂存所有待发布源版本，不因关闭此选项取消。磁盘暂存失败会安全停止，不绕过完整性与源清理要求，不提供不安全的流式回退。
- 全局忽略文件扩展名：默认 `clfstmp;parts;tmp;downloading;aria2;temp;temp_video;~#0`。去掉前导点、转小写并去重。后台上传请求在读取正文前拒绝，备份扫描跳过对应文件；这不是存储文件不可见规则，不自动删除已有文件，也不修改 STRM/CAS/ED2K 扫描规则。
- 扩展名标签使用共享的浅星空蓝紫渐变表面，日夜主题分别适配；与备份规则和115监控的筛选标签一致。只调整标签配色，内层输入框仍使用原表面层级，悬浮/键盘聚焦移除交互及即时保存规则不变。
- 临时文件位置：可填写或选择容器内绝对目录，留空默认 `/data/cache/transfer`（自定义data目录时随之改变）。用于CAS远程下载计算、备份源暂存/同步阶段、上传与挂载写入暂存；更改只影响后续暂存，不搬动正在使用的文件。目录无权限或空间不足时停止，不自动回退其他磁盘。缩略图、索引和解析预览属于运行数据而非此临时位置。

限速适用于经过本项目的文件接收、云盘上传正文、代理下载、WebDAV/FUSE 受控正文读写路径，不能限制浏览器的 302 直连、上游内部复制/离线秒传及其他客户端绕过本项目的网络流量。接口请求、获取直链和哈希计算本身不计作上传流量。115 本地挂载原有每池两路、每路 50 MB/s 的限制仍生效，与全局限制同时取更严格者。

115 单段及分段上传、移动、天翼、夸克、OpenList、WebDAV 发布共享上传控制。接收暂存与向云端发布属于两段实际 IO，均消耗该方向预算，不能把设置速度理解为最终云端净速度。FUSE 磁盘缓存命中不重复计算上游下载字节。删除传输任务会取消其子上下文和阻塞读取，不等同于撤回已被上游接受的数据。真实云盘账号及 Linux FUSE 内核行为仍需现场验证。

115大于16 MiB的正文使用顺序分片初始化，携带既有SDK的`sequential`、`x-oss-enable-sha1`及OSS UA，再逐片上传并确认回调；不通过放开权限或重放未知写入解决失败。115明确返回`upload_allowed:false`时，在计算摘要及秒传/正文提交前停止；账号单文件额度缺失或超出也单独说明，不猜测有上传权益。错误按读取上传凭据、检查上传权限、摘要计算、秒传握手、获取OSS票据、初始化/上传/合并分片和回调确认区分。OSS只展示HTTP状态和本地白名单错误码（例如AccessDenied、SecurityTokenExpired），不显示上游错误正文、RequestId、签名地址或凭据；未知码仍脱敏。备份上传也保留本地构造的失败阶段，WebDAV/OpenList写入保留HTTP状态和取消/超时原因。旧日志中已丢失的细节无法事后恢复，`0/总字节`不单独证明权限不足或端口缺失。

FUSE文件句柄的传输绑定服务生命周期，而非一次Open/Create请求的上下文；go-fuse会复用请求取消信号，不能把该信号一直存到句柄关闭。每次实际发布只合并当前回调取消、传输删除和服务停止，回调结束不污染下一次操作。失败仍保留原暂存文件，已接受的上游写入不盲目重提。本地挂载不需要额外TCP/UDP上传监听端口；参考LitePan Compose中的42069用于其内置磁力/BT节点通信，不是go-fuse端口。容器仍需`/dev/fuse`及相应权限，实际写入还受只读设置、挂载UID/GID/模式、暂存空间和云盘上传授权约束，不能靠新增42069映射绕过。

## 备份资源设置

- 暂停双向同步：保留完整扫描、特征校验和操作规划，把名称、来源/目标序号及删除意图记录到 `/data/runtime/backup-plans`。不创建同步标记、目标目录，不复制、改名或删除，也不推进基线。恢复执行会重新扫描，不直接重放旧计划。执行期间开启暂停会在后续变更边界停下，不撤回已经被上游接受的变更；不是跨服务原子暂停。
- 队列上限：默认 10000，0 为无限制。完整范围和重叠预检仍先完成，随后将操作描述符加密落盘，执行时仅按上限载入待处理项，消费后释放。这不是扫描项数上限，不截断备份，也不取消已有的单次 100000 项安全上限。清单使用 AES-GCM 认证加密，执行前完整验证；正常结束删除，异常退出的遗留清单不重放。
- 队列下限：0 表示自动取上限的一半。队列消耗到下限时补到上限；上限为 0 时下限也为 0。它限制解密后的待执行描述符数量，不限制完整安全预检、删除/源清理和双向基线所需的索引内存，也不限制安全暂存文件的磁盘空间。
- 最大并发扫描数：默认 1，可配置 1 至 16。不同规则可提交后排队；同一规则不重复运行。扫描结束后归还扫描槽。目标发布、删除与源清理仍全局串行，以防不同备份范围互相覆盖；不是文件上传并发数。扫描等待、暂存读取、限速等待和执行队列均响应任务停止/服务取消。

源清理仍要求全部目标成功、校验通过、源未变化。跳过、失败、取消不清理源。双向同步仍先暂存全部待发布源版本，发布后复查再保存基线，不因资源设置降低原有安全要求。

每次执行固定使用同一份忽略扩展名快照；执行中更改该过滤配置会阻止后续发布、删除和基线推进，须重新扫描。已发生的跨服务变更无法回滚为原子事务。

## 接口

管理员会话保护 `GET/PUT /api/transfer/settings` 和 `GET/PUT /api/backup/settings`。保存即对后续申请槽和正文限速生效。系统传输设置保留等宽两列：速度与临时位置、任务限制；全局忽略扩展名横跨下方整行。输入及选择自动保存，短时合并输入、串行提交，修改期间不被旧响应覆盖；失败保留输入并显示重试，离开页面提交最后有效更改。独立备份设置页保留原保存按钮与返回导航。
