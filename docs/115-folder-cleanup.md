# 115 文件夹清理

“我的插件”中位于115同播复制之后。打开插件、添加文件夹，选择启用的115存储下的非根目录，设置五字段Cron和整数天数阈值，二次确认后保存。新配置默认未启用，总开关启用另需确认；Cron相邻触发[至少15分钟](cron-policy.md)。

- 阈值默认0：每次计划清理该目录下全部普通文件；5表示清理存在严格超过5天的文件，边界正好5天保留。优先使用创建时间，缺失时使用修改时间；正阈值下时间均未知或1970年零时间的文件保留。
- 递归处理文件后倒序检查空子目录，仅删除已确认空的子目录，始终保留选定目录。互相包含或重复的规则拒绝保存。最多100条规则，每次完整预扫最多10000项/64层，10分钟超时；预扫失败不开始删除。
- 使用现有115删除协议移入回收站，不永久清空回收站，不需要回收站PIN。存储若配置为尚未支持的115永久删除模式则拒绝规则，须先调整存储删除方式。
- 保存只读核验并记录选定目录的完整祖先身份。执行与每次删除前复查规则、启停、存储授权、祖先路径、文件身份和内容信息；变化或取消停止后续操作。115删除提交前额外读取一次子目录，不能确认仍为空时不提交删除；这个内部空目录限制不对网页普通删除开放。上游不提供原子“仅空目录删除”，最后查询和删除间仍存在外部并发写入竞态，不承诺跨云端原子事务。
- 每次删除前持久保存意图，明确成功后保存确认回执；错误或回执未知不自动重删。重启保留意图且不补跑错过计划。只有确认成功且超过30天的回执可淘汰；未知意图保留，总回执20000条时停止并要求核对。

规则位于`/config/state.json`的`folderCleanup`，身份回执位于`/data/runtime/state.json`的`folderCleanupReceipts`。配置备份不包含回执，配置导入保留现有回执；迁移须共同备份配置、主密钥和运行态。删除存储会移除其规则，不清理云文件。执行结果及逐项成功写入运行日志，不输出Cookie或签名链接。

保存规则后独立更改存储根目录或删除模式，不应造成容器启动失败；旧规则可读取，但执行时仍严格复核并停止不合规规则，日志报告原因。重新编辑/导入仍须满足当前存储范围及删除能力，不自动扩大清理范围。

本功能由协议模拟测试验证，真实115账号的权限、回收站行为和并发环境仍需部署验收。
